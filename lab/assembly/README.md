# Assembly Lab

獨立的零件組裝與本地試飛實驗，目前尚未接進主遊戲。

```sh
cd lab/assembly
npm install
npm run dev -- --port 5199
npm run check
npm run build
```

開啟 `http://127.0.0.1:5199`。預設載入兩級火箭，也可按「新建」從指令艙開始。

## 操作與驗收

1. 在左側選零件，再點火箭上的綠色接點。下方選單可選新零件的 `top` 或 `bottom`，方向由接點法向量決定。
2. 點零件選取，在右側調整燃料量、執行級數，或拆除該零件及其子樹。燃料滑桿放開後更新質量與重心。左鍵拖曳旋轉、右鍵平移、滾輪縮放，「置中」重設視角。
3. 級數依 0 → 1 → 2 執行，可使用不連續的數字。同級先分離、再點火；沒有級數的引擎或分離器會阻止試飛。
4. 「匯出 JSON」儲存飛行器；「匯入」會先驗證資料再替換現有組裝。可測試調低燃料、變更級數後匯出／匯入，再試飛。
5. 按「試飛」，Space 或「下一級」執行級數。預設節流 100%；Shift 增加、Ctrl 減少、X 設為 0，也可使用滑桿。W/S、A/D、Q/E 施加俯仰、滾轉、偏航的測試扭矩。可暫停或回到原始組裝重新修改。
6. 兩級範例：Space 點火下級；上升後 X 關閉推力，再 Space 分離並點火上級，Shift 恢復節流。觀察物理群從 1 變成 2、燃料與重心改變，下級保留獨立運動。放大／旋轉確認接點、選取高亮、重心與分離畫面。

瀏覽器畫面與互動由使用者驗收。`npm run check` 驗證接點幾何、資料拒絕、子樹操作、供油連通、JSON 往返，以及真實 Rapier 的地面接觸、推力／Isp 耗油、分離位置／動量、燃料耗盡與自訂組裝試飛。

## 資料与執行方式

- `src/model.ts`：零件定義、模組、資源、父子接合樹與純資料運算。零件實例只存定義 ID、燃料、級數與接點關係；位置和旋轉由接點推導。JSON 有版本欄位，目前為 `1`。
- `src/runtime.ts`：將組裝編譯成 Rapier compound rigid body。分離切斷指定接點的連線，重新計算連通群；新群保留原來的姿態及速度場，接點施加等大反向分離衝量。
- `src/main.ts`：Three.js WebGL2 編輯器與試飛介面。匯出的組裝資料也是試飛的輸入，沒有另一份固定火箭。
- 燃料只在允許 crossfeed 的連通零件間流動；分離器禁止跨接。耗油依 `推力 / (Isp × g₀)` 計算；燃料不足會縮減當步推力，燃料質量與慣量同步更新。

採用 kg、m、N、s；質心在各零件的作者原點，慣量先用外接圓柱近似。分級數字從小到大，與 KSP 的 `inverseStage` 不同。正常資料錯誤會顯示原因；初始化或非預期錯誤會 panic，不切換替代後端。

## KSP 參考

參考本機 `../ksp-decompile/reference/decompiled/Assembly-CSharp/` 的概念，未複製其程式或素材：

- `Part.cs`、`AttachNode.cs`：零件擁有 modules/resources/nodes，組裝以父子樹及成對接點表示。
- `ShipConstruct.cs`：飛行器是可序列化的零件集合。
- `ModuleEngines.cs`：推力、Isp、推進劑消耗的關係。
- `ModuleDecouplerBase.cs`、`ModuleDecouple.cs`：切斷指定 explosive node，而不是假定永遠切斷父連線；本 lab 的分離器使用 `top`。
- `EditorLogic.cs`：零件庫、選取零件、組裝與分級介面的職責。

## 本輪範圍

目前六種零件、四種模組，先做堆疊接點。尚未做表面接合、對稱、自由位移／旋轉、碰撞重疊檢查、結構彎曲或破壞、多種燃料與供油優先序。編輯器允許錯誤點火順序，級數需自行安排。

試飛場是平地與固定重力，沒有軌道、大氣阻力或行星 scenery。控制扭矩僅供測試，尚未建模 SAS／反作用輪；所有已點火的引擎包含拋棄級目前共用節流指令，暫停仍允許執行級數。這些行為在 lab 先驗證後，再決定主遊戲需要的介面。
